# SOP Library

## 1. Relocation Intake

| Field | SOP |
| --- | --- |
| Trigger | New relocation intent or consultation request |
| Goal | Convert raw move request into a qualified, owned execution case |
| Steps | Review intent, confirm timeline and family context, open request, assign owner, define next required data, offer consultation or move into package path |
| Escalation condition | Complex family relocation, legal ambiguity, high urgency, or unclear scope |
| System updates required | Create request, set priority, create qualification tasks, log first communication |
| Mistakes to avoid | Treating relocation like generic lead intake, skipping timeline qualification, failing to assign owner |

## 2. Business Setup Intake

| Field | SOP |
| --- | --- |
| Trigger | New business setup request or founder consultation |
| Goal | Convert a vague company setup request into a scoping-ready case |
| Steps | Confirm business goal, identify likely setup path, determine whether consultation is required, create request, schedule next action |
| Escalation condition | Unusual structure, compliance uncertainty, banking sensitivity, or unclear licensing path |
| System updates required | Request record, monetization stage, consultation task or quote task, operator note |
| Mistakes to avoid | Giving false certainty too early, discussing pricing without scope, leaving the user in generic follow-up limbo |

## 3. Lifestyle And Booking Requests

| Field | SOP |
| --- | --- |
| Trigger | New lifestyle, nightlife, stay, transport, or experience request |
| Goal | Decide whether the request is self-serve, assisted, or concierge-led |
| Steps | Review intent, assess complexity, route to booking flow or create request, capture any urgency, confirm payment path |
| Escalation condition | Multi-service, group, VIP, urgent, or supplier-dependent requests |
| System updates required | Booking candidate or request record, timeline entry, quote task if needed |
| Mistakes to avoid | Treating custom requests like listings, promising availability before confirmation, failing to collect commercial commitment |

## 4. High-Value Custom Requests

| Field | SOP |
| --- | --- |
| Trigger | Custom request with unclear scope, high spend, urgency, or multiple dependencies |
| Goal | Protect service quality while converting the request into a paid and executable plan |
| Steps | Clarify scope, assign senior owner, collect missing details, build quote or deposit path, confirm operator and partner plan |
| Escalation condition | User is VIP, request is time-critical, supplier confidence is low, or execution touches multiple categories |
| System updates required | Priority upgrade, owner assignment, quote task, risk flag |
| Mistakes to avoid | Free consulting without scope control, unpriced execution promises, hidden handoffs |

## 5. Membership Customers

| Field | SOP |
| --- | --- |
| Trigger | Member request enters queue |
| Goal | Deliver visible priority handling and continuity |
| Steps | Confirm tier, apply priority logic, review history, respond within member SLA, use preference memory, log outcome |
| Escalation condition | SLA risk, service failure, or member dissatisfaction |
| System updates required | Membership flag on request, updated SLA target, operator action log |
| Mistakes to avoid | Selling membership without differentiated handling, making members repeat context, treating tiers as cosmetic |

## 6. Quote Follow-Up

| Field | SOP |
| --- | --- |
| Trigger | Quote sent and still pending |
| Goal | Increase quote conversion without sounding desperate |
| Steps | Review quote age, review user segment and urgency, send contextual follow-up, highlight next step, adjust if scope changed |
| Escalation condition | High-value quote close to expiry, repeated silence from premium lead |
| System updates required | Timeline entry, follow-up task, quote status note |
| Mistakes to avoid | Generic chase messages, too many follow-ups without value, failing to surface quote blockers |

## 7. Failed Partner Fulfillment

| Field | SOP |
| --- | --- |
| Trigger | Partner misses SLA, rejects request, or fails delivery |
| Goal | Recover trust and restore execution quickly |
| Steps | Confirm failure details, reassign partner or internal workaround, inform user with controlled message, log failure reason, update recovery timeline |
| Escalation condition | VIP user, time-critical failure, repeated partner issue |
| System updates required | Partner issue flag, operator action, timeline note, updated request status |
| Mistakes to avoid | Leaving the user uninformed, blaming the partner directly, failing to record the partner issue structurally |

## 8. Urgent Escalation

| Field | SOP |
| --- | --- |
| Trigger | Request marked urgent or at risk of SLA breach |
| Goal | Move the case to immediate action without breaking accountability |
| Steps | Elevate priority, assign owner if missing, review blockers, confirm commercial state, start immediate outreach or recovery |
| Escalation condition | No owner, no partner response, no payment clarity, or no user response where action is blocked |
| System updates required | Priority change, escalation action, owner update, timeline note |
| Mistakes to avoid | Marking everything urgent, escalating without ownership, hiding stalled payment or quote issues |

## 9. Refund Or Service Recovery

| Field | SOP |
| --- | --- |
| Trigger | User requests refund or service materially underdelivers |
| Goal | Protect long-term trust while managing commercial downside |
| Steps | Review promise versus delivery, classify fault, choose refund, credit, or recovery action, communicate clearly, close with documented outcome |
| Escalation condition | High-value user, public reputation risk, repeated failure pattern |
| System updates required | Payment update, operator action, issue classification, partner impact note |
| Mistakes to avoid | Arguing with the user before reviewing facts, silent partial refunds, failing to learn from the incident |

## 10. Off-Platform WhatsApp Control

| Field | SOP |
| --- | --- |
| Trigger | User or operator continues execution through WhatsApp or off-platform messaging |
| Goal | Preserve context, attribution, and revenue control |
| Steps | Log summary back into DALC, keep quote and payment links inside DALC, record any partner commitments, keep request ownership visible |
| Escalation condition | Commercial terms are moving fully off-platform, supplier is bypassing DALC, or quote context is disappearing |
| System updates required | Conversation timeline entry, payment status note, operator action log |
| Mistakes to avoid | Letting WhatsApp become the source of truth, allowing payment leakage, losing auditability |
