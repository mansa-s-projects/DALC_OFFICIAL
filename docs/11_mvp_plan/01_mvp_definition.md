# MVP Definition

## MVP Thesis

The DALC MVP is not a broad Dubai super app.

The DALC MVP is a premium intent-to-execution system for a narrow but highly monetizable wedge:

**relocation, business setup, and high-value concierge requests handled through a strong command entry, operator workflow, quote path, and payment path.**

## What Absolutely Must Exist

| Must exist | Why it is non-negotiable |
| --- | --- |
| Command-style intake | DALC must capture raw user intent directly |
| Intent classification layer | DALC needs a decision engine, not disconnected forms |
| Request creation and tracking | High-value demand must become operational objects |
| Operator queue and request console | Without this, complex requests collapse into inbox chaos |
| Quote and payment flow | DALC must convert intent into revenue, not just leads |
| Paid consultation product | Fastest trustworthy monetization path |
| One strong relocation flow | Core consumer wedge |
| One strong business setup flow | Core founder wedge |
| One premium concierge flow | Cross-category monetization engine |

## What Should Be Manually Handled Behind The Scenes

1. quote creation for complex requests
2. partner verification and assignment
3. relocation planning logic for edge cases
4. school, housing, and banking recommendations
5. bespoke bundle creation
6. most operational escalation and recovery logic

Manual execution is acceptable in MVP. Invisible chaos is not.

## What Should Not Be Built Yet

1. massive self-serve supplier inventory
2. fake fully autonomous AI fulfillment
3. deep user preference engines across every category
4. broad membership program before service reliability exists
5. heavy marketplace mechanics like vendor dashboards and broad public supply upload flows
6. complex real-time pricing engines

## What Fake Polish Should Be Avoided

| Fake polish | Why it is harmful |
| --- | --- |
| Endless luxury visuals with weak execution | Creates a brand promise DALC cannot operationally support |
| Chatbot theater | Makes DALC look smarter than it is while exposing weak backend depth |
| Massive category breadth | Creates noise, not clarity |
| "Coming soon" premium features everywhere | Signals ambition without trust |
| Membership before benefits exist | Damages long-term retention economics |

## Smallest Version That Can Still Feel Premium And Powerful

The smallest DALC that can still feel premium is:

1. a sharp homepage with command input
2. a relocation consultation and request flow
3. a business setup consultation and request flow
4. a concierge request and quote flow
5. a premium operator-driven backend experience hidden behind the scenes

If these are executed well, DALC will feel like a serious system even if most fulfillment is still manually coordinated.

## Best Launch Wedge

The best launch wedge is:

**high-intent users already committed to Dubai who need relocation, business setup, or premium execution support.**

This wedge is better than tourism-first or nightlife-first because it creates stronger urgency, higher trust, better margins, and richer follow-on demand.

## What Success In The First 30 Days Looks Like

| Success signal | Target direction |
| --- | --- |
| Serious requests captured | DALC consistently captures real high-intent demand |
| Paid consultations sold | Proof that the market trusts the front door |
| Packages or quotes accepted | Proof DALC can convert beyond intake |
| Request fulfillment | Proof DALC can deliver, not just sell |
| Follow-on requests | Proof the relationship extends beyond one task |

## Metrics That Matter

1. command input to consultation conversion
2. consultation to package or quote conversion
3. request to payment conversion
4. time to first response
5. time to quote
6. fulfillment completion rate
7. repeat request rate

## What To Ignore Initially

1. low-intent content traffic
2. broad awareness vanity metrics
3. huge supplier onboarding counts
4. complex member perks
5. overfitted AI sophistication without operational proof

The DALC MVP should optimize for paid execution, not visual completeness.
